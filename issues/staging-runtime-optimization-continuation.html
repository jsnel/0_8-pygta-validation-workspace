Bottleneck and change

Before
list(amplitude_axis)   # scalar DataArrays
list.index(...)        # xarray equality, per comparison
After
np.asarray(amplitude_axis).tolist()   # once
list.index(...)                       # str equality

Cause

OptimizationObjective.get_dataset_amplitudes receives an xarray coordinate. list(amplitude_axis) produces scalar DataArrays, so each list.index comparison invokes xarray's equality, coordinate alignment and index construction. The existing profile identifies hundreds of thousands of these comparisons; the previous gather vectorization retained this overhead.

Change

Convert the coordinate with np.asarray(amplitude_axis).tolist() once before the gather. Ordinary Python string comparisons replace xarray equality. The selection order and all numerical operations remain unchanged. There is no cache, cross-fit state, solver change, extra dependency or workload special case.

Regression coverage

  • ndarray and xarray coordinate inputs
  • reordered global indices
  • differing per-slice amplitude layouts
  • a second reconstruction after mutating estimates, to detect accidental reuse

Measurement method

Probe
benchmark_staging_continuation.py runs the original notebook cells through the last optimizer cell in a fresh process. Earlier setup and plotting stay outside timing; later plotting is not executed.
Timed interval
The public Scheme.optimize call: validation, solving, complete reconstruction and parameter-error calculation.
Phase timers
Lightweight wrappers separately time initialization, objective calculation and reconstruction. These phases are reported alongside, never substituted for public-call time.
Memory
A 20 ms RSS sampler runs only during the public call. Neither cProfile nor tracemalloc is enabled. RSS includes objects retained by prior cells and is not an isolated per-fit allocation measurement.
Driver
run_staging_continuation.py alternates branch order per repetition. PFID: one warmup plus three timed repetitions. Standard examples: one plus five.
Snapshots
Captured only in warmups, after the public-call timer stops. compare_staging_snapshots.py recursively checks all native reconstructed fields, coordinates, attributes, metadata, parameter tables and optimization information.
Failed probe
The first PFID baseline probe failed after its first optimize call because pickling an entire Result encounters a dynamically generated model class. pfid-baseline-warmup/ is retained as failed evidence and excluded. The rerun pfid-baseline-warmup2/ stores plain result-field mappings and completed.

Controlled-workload constraint

PFID cannot be made to iterate

Both original PFID real calls have zero free parameters, nfev=1 and njev=0, and terminate with No free parameters to optimize. They are meaningful public optimizer and reconstruction workloads, but they cannot perform 4–8 nonlinear steps by perturbing free starting values. Changing fixed/free flags would change the requested optimization problem and is outside the contract. The limitation is reported rather than relabelling result reconstruction as nonlinear optimization.

What "success" means

Staging's optimization_info.success means that SciPy returned a result, even when it exhausted its evaluation budget. The probe also captures SciPy's actual success and status; convergence claims use the actual termination. The original two-dataset and spectral-guidance calls both exhaust their budgets (17 and 21 evaluations) and must not be described as converged.

Rejected ideas and remaining risks

Rejected

  • Residual gathering and SVD rewrites. The supplied profile and focused experiment identify amplitude-label equality as the avoidable cost. Broader arithmetic changes add risk without being necessary for this gain.
  • Cache, parameter-dependent reuse, buffer sharing, solver replacement, matrix reassociation. None introduced. The earlier matrix-copy removal was already rejected for changing optimizer trajectories and remains reverted.
  • Tiny two-dataset perturbation. Rejected for doing too few genuine steps.
  • Freeing PFID parameters to manufacture iterations. Rejected as a change to the optimization problem.

Remaining risks

  • No overall two-dataset speedup or memory improvement is claimed. PFID timing variance and existing numerical sensitivity remain material limits.
  • The inherited Gaussian shift defect, the unreconciled dependency lock and the original examples' non-convergence remain explicitly documented. The passing current-staging comparison does not hide them.
